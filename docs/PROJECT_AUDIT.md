## 3. אימות גישה לחשבון ה־Live האמיתי

בסשן הזה מחובר קונקטור רשמי של Interactive Brokers (MCP) לחשבון ה־Live שלך. בוצעו קריאות **Read-Only בלבד** (סיכום חשבון, יתרות, פוזיציות, עסקאות, ביצועים). לא נשלחה ולא תישלח שום הוראת מסחר.

ממצאים מהחשבון האמיתי שהשפיעו על התכנון (ללא פרטים מזהים וללא סכומים — בכוונה, כדי לא לשמור מידע פיננסי אישי ב־Git):

| ממצא | השלכה על התכנון |
|---|---|
| מטבע הבסיס של החשבון: USD | כל החישובים מנוהלים במטבע בסיס + המרה לתצוגה |
| קיימות יתרות מזומן ביותר ממטבע אחד (USD ו־ILS), כולל יתרה שלילית ב־USD (חוב מרג'ין) | טיפול רב־מטבעי אמיתי חובה מהיום הראשון; אסור להניח "הכול דולרי" |
| חשבון מרג'ין (קיימים Buying Power, Margin Requirements, מוני Day-Trades) | הדשבורד חייב להציג Margin/Excess Liquidity; מנוע הסיכונים מתייחס למינוף |
| הנכסים הנוכחיים: מניות אמריקאיות (STK) | מודל הנתונים תומך בכל סוגי הנכסים, אך ה־UI ימוקד תחילה במניות |
| היסטוריית החשבון מתחילה ב־2026-02-17 | טווח קצר מ־365 יום ⇒ **Flex Query אחת מכסה את כל ההיסטוריה מאז פתיחת החשבון** |
| עסקאות כוללות עמלות (Commission) ו־Realized P&L פר עסקה | ניתן לבנות Trade Cycles מלאים כולל עלויות |
| IBKR מחשבת בעצמה TWR יומי (Portfolio Analyst) | ישמש כמקור השוואה (Reconciliation) לחישובי המערכת |

## 4. בדיקת התיעוד הרשמי של IBKR (בוצעה 2026-07-13)

נבדקו המקורות הרשמיים העדכניים. עיקרי הממצאים (הפירוט המלא וההשוואה — ב־IBKR_INTEGRATION.md):

1. **Web API (Client Portal API)** — לקוחות פרטיים (Retail) יכולים להתחבר **רק** דרך Client Portal Gateway (תוכנת Java מקומית) עם התחברות ידנית בדפדפן; OAuth 2.0 ללקוחות פרטיים "נשקל לעתיד, אין תאריך". Session פג בערך כל 24 שעות.
2. **TWS API** דרך IB Gateway — ממשק socket יציב עם streaming אמיתי; ספריית Python המתוחזקת כיום היא `ib_async` (ממשיכת `ib_insync` שאינה מתוחזקת עוד). ל־IB Gateway יש הגדרת **"Read-Only API"** שאוכפת קריאה־בלבד בצד של IBKR עצמה.
3. **Flex Web Service** — משיכת דוחות מוגדרים-מראש (Flex Queries) ב־HTTPS עם Token (תוקף מוגדר, 6 שעות עד שנה) + Query ID. קריאה־בלבד מטבעו. מגבלת קצב בפועל: בסביבות בקשה אחת לשנייה, והדוח נוצר אסינכרונית (בקשה → המתנה → הורדה). זהו המקור המלא ביותר להיסטוריה: עסקאות, עמלות, דיבידנדים, ריבית, הפקדות/משיכות, המרות מט"ח, Corporate Actions ו־NAV יומי.

**ההחלטה (מנומקת ב־IBKR_INTEGRATION.md):** שילוב של **IB Gateway + ib_async** לנתונים חיים (עם אכיפת Read-Only בשלוש שכבות) ו־**Flex Web Service** להיסטוריה מלאה.

## 6. סיכונים ומגבלות שזוהו כבר עכשיו

1. **לא ניתן לבדוק חיבור Gateway חי מסביבת הפיתוח** — האימות הסופי של שלב 3 יתבצע על ה־Mac שלך, עם צ'קליסט בדיקה מסודר ב־RUNBOOK.md. מה שכן אומת כבר עכשיו: מבנה הנתונים האמיתי של החשבון (דרך הקונקטור), כך שהקוד נכתב מול צורת נתונים אמיתית ולא מדומיינת.
2. **הרשאות Market Data** — אם אין מנוי לנתוני זמן־אמת, IBKR מחזירה מחירים מושהים (Delayed, ~15 דק'). המערכת מציגה זאת במפורש ולא מתחזה לזמן־אמת.
3. **IB Gateway דורש התחברות מחודשת תקופתית** (מדיניות של IBKR: ניתוק יומי מתוזמן, ואימות דו־שלבי לפחות פעם בשבוע). המערכת מתוכננת לשרוד את זה: הנתונים האחרונים נשמרים, מוצג זמן עדכון אחרון, ו־Reconnect מבוקר.
4. **Executions דרך ה־Gateway מוגבלים לימים האחרונים בלבד** — לכן ההיסטוריה המלאה מגיעה מ־Flex, וה־Gateway משמש לזמן־אמת בלבד.
