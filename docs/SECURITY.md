# SECURITY — אבטחת מידע

המערכת מטפלת במידע פיננסי רגיש ולכן האבטחה היא דרישת יסוד, לא תוספת.

## 1. מודל האיום וההגנה הבסיסית

המערכת רצה **מקומית בלבד** על ה־Mac שלך:
- כל השירותים (Backend, Frontend, PostgreSQL) מאזינים על `127.0.0.1` בלבד. שום פורט לא נחשף לרשת.
- IB Gateway מוגדר עם Trusted IP = 127.0.0.1 בלבד, ולעולם לא נחשף לאינטרנט.
- אין Analytics חיצוני. מודול החדשות Finnhub כבוי ללא `FINNHUB_API_KEY`.
  כשהוא מופעל, סמלי שמונה ההחזקות הגדולות וטווח תאריכים נשלחים ל־Finnhub
  לקבלת חדשות. כמויות, שווי, מספר חשבון ועסקאות אינם נשלחים אליו.
- אם בעתיד תרצה הרצה על שרת פרטי — RUNBOOK כולל דרישות מינימום (VPN/Tailscale, אין חשיפה ישירה, נעילת ממשק) — לא לפני כן.

## 2. סודות (Secrets)

| כלל | מימוש |
|---|---|
| סודות מקומיים בלבד | `.env` מקומי; Flex שנשמר דרך המסך מאוחסן גם בטבלת settings המקומית ב־PostgreSQL |
| שום סוד ב־Git | `.gitignore` חוסם `.env*` (פרט ל־`.env.example`), קבצי DB, גיבויים, uploads |
| `.env.example` | כל המפתחות עם ערכי placeholder בלבד |
| סיסמת IBKR | **לעולם לא מגיעה למערכת** — היא מוקלדת רק בתוכנת IB Gateway של IBKR עצמה |
| Flex Token | נשמר ב־`.env` או, אם הוזן במסך, מוצפן לפני כתיבה ל־PostgreSQL המקומי; אינו מוחזר מלא ל־UI וממוסך אוטומטית בלוגים |
| סיסמת PostgreSQL | נוצרת אקראית ב־setup, נשמרת ב־`.env` |
| קישור לחשבון | fingerprint מבוסס HMAC בלבד; מספר החשבון הגולמי אינו נשמר בהגדרה |

## 3. הסתרת פרטי חשבון

- מספר החשבון מוצג ב־UI ממוסך בלבד (`U***123`).
- בלוגים מספר החשבון תמיד ממוסך; שכבת הלוגים כוללת processor שמסנן תבניות רגישות (account id, token) לפני כתיבה.

## 4. Read-Only מול IBKR

שלוש שכבות (פירוט ב־IBKR_INTEGRATION.md): הגדרת Read-Only API ב־Gateway (אכיפת IBKR), `readonly=True` בחיבור, והיעדר מוחלט של קוד שליחת הוראות. אם אי־פעם יתווסף מודול מסחר — יהיה מודול נפרד עם הרשאות נפרדות, אישור כפול ו־Audit מלא, ורק לבקשתך המפורשת.

## 5. הגנת קלט ופלט

- **Validation**: קלטי API עוברים סכמות Pydantic; ה־frontend כתוב TypeScript
  והשדות הרגישים מוגבלים באורך בצד השרת.
- **SQL Injection**: גישה ל־DB רק דרך SQLAlchemy עם פרמטרים קשורים — אין שרשור SQL ידני.
- **XSS**: React מבצע escaping כברירת מחדל; אין שימוש ב־`dangerouslySetInnerHTML` על קלט משתמש; הערות יומן מוצגות כטקסט, לא כ־HTML.
- **Host + CORS + Origin guard**: Host שאינו localhost נדחה נגד DNS
  rebinding; ה־Frontend המקומי בלבד מורשה, ופעולות שמשנות מצב נדחות אם הגיעו
  מ־Origin אחר.

## 6. Audit Log

ריצות Flex נשמרות בטבלת `sync_runs` עם סטטוס ומטא־דאטה מסונן. אירועי
חיבור/ניתוק ושגיאות תפעוליות נרשמים בלוג ממוסך. זהו רישום תפעולי, לא מערכת
Audit תאימות מלאה.

## 7. גיבוי ומחיקה

- `scripts/backup.sh` — יוצר dump דחוס ומאומת של ה־DB + תיקיית הקבצים,
  ושומר 14 זוגות אחרונים. התיקייה מוגדרת `0700` והקבצים נוצרים עם
  `umask 077`; Flex Token שנשמר דרך ה־UI מופיע בגיבוי רק כ־ciphertext.
  לשחזור במחשב אחר חייבים לשמור בנפרד ובאופן מאובטח גם את `.env`/מפתח ההצפנה.
- מחיקת נתוני העבודה: `scripts/reset_data.sh` עם אישור מפורש — מוחק את
  volumes המקומיים. גיבויים חיצוניים אינם נמחקים.
- הגיבויים לעולם לא נכתבים לתיקיית הריפו (נמצאים ב־`~/.ibkr-dashboard/backups` כברירת מחדל) — כדי שלא יגיעו ל־Git בטעות.

## 8. מה נשמר ומה לא

| נשמר מקומית | לא נשמר בשום מקום |
|---|---|
| עסקאות, פוזיציות, NAV, תנועות מזומן, יומן אישי, הגדרות | סיסמת IBKR |
| Flex Token (ב־`.env` או מוצפן ב־PostgreSQL המקומי כשנשמר דרך ה־UI) | פרטי כרטיס/בנק (לא נגישים בכלל דרך ה־API) |
| לוגים תפעוליים (ממוסכים) | Tick data רציף |

## 9. תלויות וקוד

- נעילת גרסאות מלאה (`uv.lock`, `pnpm-lock.yaml`).
- אין הרצת קוד דינמי על קלט.
- CI מריץ Ruff, בדיקות backend מול PostgreSQL ייעודי, ESLint, בניית Next.js
  ובניית images. Workflow ההפצה מייצר גם SBOM ו־provenance.
